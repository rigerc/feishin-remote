# Working on the Feishin Remote website

This fork began as [Astro Rocket](https://github.com/hansmartensdev/Astro-Rocket). The original theme guidance is preserved in `AGENTS.upstream.md`; keep its advice on accessible components, stable design tokens, and reliable checks wherever compatible.

## Routes and content

- `/` is `src/pages/index.astro`, the Feishin Remote homepage driven by `src/config/project.config.ts`. It shows app captures from `public/media/`, generated by `tool/media.sh` in the repository root and never committed.
- `/privacy/` and `/support/` are plain pages in `src/pages/`. Keep their URLs stable; they may be linked from app stores.
- `/docs/` and nested documentation pages are generated by Starlight from `src/content/docs/docs/*.md`.
- `src/content.config.ts` registers Starlight's `docs` collection alongside retained upstream collection schemas.
- `src/config/nav.config.ts` contains primary and footer navigation.
- `src/config/branding.ts` contains the name, repository, color, and logo path; `src/config/site.config.ts` controls SEO and site metadata.
- Modules that `astro.config.mjs` loads (`branding.ts`, `i18n.config.ts`, `site-url.ts`) must not import anything, not even JSON: that closes Vite's module runner before the build hooks run, and the favicon step fails with "Vite module runner has been closed".
- Upstream blog, projects, services, about, and contact routes were removed deliberately. Do not reintroduce them as a generic theme showcase.

## Automated media

- `tool/media.sh` (repository root): app screenshots and walkthrough video from the real Flutter app against a fake Feishin desktop. Required before `pnpm check:site` passes.
- `pnpm media:capture`: website screenshots using Playwright, requires a locally running preview server.
- `pnpm media:video`: website walkthrough recording, then FFmpeg MP4 conversion, requires a preview server.
- `media-output/` and `public/media/` are generated, gitignored output. Do not check rendered media into the repo unless expressly requested.
- The repository's `.github/workflows/website.yml` uploads generated assets as Actions artifacts and deploys Pages when enabled.

## Quality gates

Run `pnpm lint`, `pnpm check`, `pnpm test:run`, `pnpm build`, `pnpm check:site`, and `pnpm verify`, or `tool/site.sh` from the repository root. Always inspect `/` and `/docs/` visually after CSS or routing edits. If you change dependencies, regenerate and commit `pnpm-lock.yaml`; once it exists, CI should use `--frozen-lockfile`.

The upstream MIT license and attribution must remain intact.
